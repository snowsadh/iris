# Contributor guidance

- Read the README, architecture and relevant callers before editing a module.
- Keep food facts, agreements and physical outcomes distinct. Preserve report history and native stored-field positions.
- Keep permissions and quantity checks in the native command path. The browser must not become a second food ledger.
- Use the smallest complete change. Avoid speculative dependencies and abstractions.
- Run checks appropriate to the change. Native behavior requires the actual licensed runtime; host tests alone are insufficient.
- Keep credentials, vendor images and personal preparation out of Git.
- When a local `AGENT.md` is present, read it before project work. It holds the maintainer's ongoing instructions.
